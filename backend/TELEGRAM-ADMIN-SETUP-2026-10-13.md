# Управление квизом через Telegram — установка и работа
Актуально: 13 октября 2026. Код в GitHub **не разворачивает себя** в Google Apps Script и Cloudflare.

## Что готово
- Кнопки владельца по `/start` или `/admin`: «Подготовить выпуск», «Опубликовать выпуск» (с подтверждением), «Статистика», «Статус», **«Сбросить моё прохождение»**.
- Проверка администратора по `TEST_CHAT_ID`; остальным бот не выдаёт админ-кнопки.
- Таблица [вычитать_Русский язык](https://docs.google.com/spreadsheets/d/1A4D4fh9Bn8QO7jZGGvQsIWrTP-P36tqCKPi-IqjUWLM/edit) — лист `Мини_Комментарии` (21 текст, по 3 для каждого балла).
- Подготовка читает **актуальные** вопросы и комментарии из Google Sheets, но ничего не публикует. Публикация — отдельное подтверждение в боте.
- В D1 каждый опубликованный выпуск хранит **собственный неизменяемый набор комментариев**. Для каждого пользователя вариант выбирается стабильно, а не меняется при повторных открытиях.
- По кнопке «Статистика» статистика пересчитывается из актуальных ответов D1, сохраняется в `Cloudflare_Отчёт` Google Sheets и присылается администратору из сохранённого отчёта.
- Старые ответы и выпуски не удаляются.

## Однократное подключение (до применения текущая версия бота работает как прежде)
1. **Cloudflare D1**: открой базу `vychitat-quiz-db`, Console, выполни SQL из [mini-result-comments-migration.sql](mini-result-comments-migration.sql). Это `CREATE TABLE IF NOT EXISTS`, без удаления данных.
2. **Google Apps Script**, существующий проект **«Вычитать — Mini App»**:
   - Создай новый файл скрипта **MiniBotSheetsGateway.gs**; целиком скопируй [MiniBotSheetsGateway.gs](MiniBotSheetsGateway.gs). Не заменяй им `Код.gs`.
   - В существующем `Код.gs` найди `function doPost(e) {` и **сразу после открывающей скобки** добавь ровно две строки:
     ```javascript
     if (e && String(e.parameter?.bot_admin || '') === '1')
       return miniBotGatewayHandle_(e);
     ```
     Важно: второй `doPost` создавать нельзя. Архивный `MiniLauncherWebhook.gs` не устанавливать.
   - Project Settings → Script properties: создай **MINI_BOT_GATEWAY_KEY** = уникальный случайный секрет не короче 40 символов. Не отправляй его в чаты и не записывай в GitHub.
   - Deploy → Manage deployments → действующая Web app → Edit → **New version** → Deploy. Варианты доступа: Execute as **Me**, Who has access **Anyone** (доступ к операциям дополнительно защищён секретом). Сохрани текущий **/exec** URL; **не создавай второй webhook Telegram**.
3. **Cloudflare Worker** `vychitat`:
   - Settings → Variables and Secrets: добавь **GAS_BRIDGE_URL** = полный URL существующего GAS Web App, начинающийся на `https://script.google.com/macros/s/` и заканчивающийся на `/exec`.
   - Добавь **GAS_BRIDGE_KEY** как Secret = ровно то же значение, что `MINI_BOT_GATEWAY_KEY` в GAS.
   - Не меняй текущие `DB`, `BOT_TOKEN`, `TEST_CHAT_ID`, `WEBHOOK_SECRET`, `ACCESS_MODE`, `STATS_PUSH_ENABLED`.
   - Edit code → замени код Worker содержимым [vychitat-worker-release.js](vychitat-worker-release.js) → Deploy. Текущий webhook остаётся `/telegram`; заново переключать его не надо. Никаких обновлений `allowed_updates` не требуется: кнопки админа являются **reply keyboard** и приходят как обычные сообщения.
4. **GitHub Pages**: страница `quiz.html` уже обновлена в репозитории; в ней изменён только источник текста результата. Больше ничего в дизайне обновлять не нужно.

## Безопасная проверка после подключения
1. В личном чате `@posttsop_test_bot` отправь `/start`. Помимо прежней кнопки Mini App тебе придёт клавиатура администратора.
2. Нажми **«Статус»**: покажет ID активного выпуска.
3. Нажми **«Статистика»**: получишь показатели; в Google Sheets в листе `Cloudflare_Отчёт` должно обновиться поле «Обновлено».
4. Нажми **«Подготовить выпуск»**: загрузятся вопросы и комментарии. **НЕ подтверждай публикацию**, пока не подготовлены новые шесть вопросов; текущий выпуск не изменится.
5. Проверь, что пользователь с другим Telegram ID видит только стандартную кнопку теста.

## Каждую неделю
1. В `Мини_Вопросы` замени 6 вопросов, в `Мини_Комментарии` поправь или добавь варианты. D=«НЕТ» отключает строку; для каждого балла 0–6 должен остаться хотя бы один активный текст.
2. В Telegram нажми **«Подготовить выпуск»**. Бот проверит шесть вопросов и все семь групп комментариев.
3. Не позднее чем через 30 минут нажми **«Опубликовать выпуск»**, затем **«Да, опубликовать»**. Новый выпуск откроется сразу. Если вопросы совпадают с прежними, повтора не будет.
4. В любое время нажми **«Статистика»**. Бот пересчитает и сохранит текущий отчёт.

## Поделиться результатом (обновление 13.10.2026)

- Нативное Telegram-меню пересылки использует `savePreparedInlineMessage` и отправляет результат `N из 6` **вместе с той же индивидуальной подписью**, что отображается пользователю на итоговом экране.
- Подпись берётся из снимка комментариев текущего выпуска в D1; для старых выпусков без снимка используется прежний набор из семи формулировок, общий для Worker и `quiz.html`.
- В тексте больше нет отдельной ссылки «Пройти тест» или призыва «А ты справишься лучше?». Ссылка на канал остаётся в названии «вы́Читать».
- Под сообщением остаётся одна кнопка **«Проверить себя»**, ведущая в бота.
- На устаревших клиентах Telegram без `shareMessage` остаётся резервный системный `share/url`: он включает индивидуальный комментарий и одну ссылку на тест, но не умеет создавать клавиатуру под сообщением.
- Деплой: обновить `backend/vychitat-worker-release.js` в Cloudflare Worker `vychitat`. Страница GitHub Pages `quiz.html` обновится из GitHub автоматически при штатно настроенном Pages. GAS, таблицы и D1 не меняются.

## Перепроверка текущего выпуска без создания нового

После развёртывания обновлённого Worker администратор может нажать **«Сбросить моё прохождение»** (или отправить `/resetme`) и подтвердить действие кнопкой с идентификатором текущего выпуска.

- Удаляются **только** строки владельца из таблиц D1 `mini_answers`, `mini_timers`, `mini_participants` **текущего активного выпуска**.
- Участники, вопросы, другие выпуски, комментарии, Telegram-контакты и история рассылок не удаляются.
- Устаревшее подтверждение с кнопки от прежнего выпуска не сработает после активации нового выпуска.
- После подтверждения нужно **закрыть Mini App и открыть заново из бота**, чтобы заново увидеть вводный экран и первый вопрос.
- Для этой функции **не нужны изменения GAS, Google Sheets или миграция D1**: требуется обновить только `backend/vychitat-worker-release.js` в Cloudflare Worker `vychitat`, оставив все секреты и binding DB прежними.
- **Влияние на статистику:** живые проценты и счётчики D1 изменятся при удалении ответов владельца и снова изменятся после повторного прохождения. Уже отправленный подписчикам фиксированный срез на 19:00 МСК остаётся неизменным. Отчёт `Cloudflare_Отчёт` в Google Sheets можно обновить кнопкой «Статистика».
- По соображениям безопасности у обычных участников нет команды сброса. Их принцип «одна попытка на выпуск» сохраняется.

## Защита и ограничения
- Меню закрыто проверкой `TEST_CHAT_ID`. Команды `/stats`, `/prepare`, `/publish` работают только для владельца в личном чате.
- При неисправности Google Sheets / отсутствии bridge секрета новые выпуски **не публикуются**: выводится ошибка без удаления старых данных.
- Не используй старую ручную команду `cfPublishWeeklyQuiz` для новых выпусков с комментариями: для неё не предусмотрена загрузка комментариев, а новый путь — «Подготовить» → «Опубликовать» в боте.
- Если GAS возвращает HTML вместо JSON: проверь новую версию deployment и режим Anyone.
- Отдельной кнопки принудительного удаления ответов нет — каждый новый выпуск автоматически получает новую попытку, история старого остаётся.
