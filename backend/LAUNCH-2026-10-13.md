## Вечером 12 октября: подготовка, БЕЗ публикации
1. В листе «Мини_Вопросы» Google-таблицы замени ВСЕ 6 тестовых заданий реальными:
   - убери «Бла бла бла бла» из описаний;
   - проверь варианты 1–10, правильные ответы, объяснения и таймеры;
   - если у вопроса нет дополнительного текста, описание можно оставить пустым.
2. Выполни в GAS функцию **cfStageMiniQuestions**. Она обновит только черновик в D1.
   **Не запускай cfActivateNewPilot вечером:** статистика нового выпуска должна открыться
   13 октября после 19:00 МСК, а дата присваивается при активации.
3. В Cloudflare Worker `vychitat` при сохранении секретов и привязки D1 размести
   исходник `backend/vychitat-worker-release.js`. Это обновит ссылку для запуска

   INVITES_ENABLED и WEEKLY_ENABLED — `no` (или не задавай).
4. В GAS-проекте «Вычитать — Mini App» добавь отдельным скриптом содержимое
   `backend/MiniReleaseControl.gs`.
5. Вручную выполни **cfReleaseSendSelfButton** и открой итоговый экран в Telegram:
   до нового выпуска там будет предыдущий результат 4/6. Это нормально.
6. Не выполняй **cfReleaseSwitchWebhook**, **cfReleaseSwitchMenu** или **cfReleaseInvite20**.

## Утром 13 октября: порядок публикации
**До начала обязательно проверить, что шесть новых заданий готовы.**

1. GAS: **cfStageMiniQuestions** (если вечером таблица менялась ещё раз).
2. GAS: **cfActivateNewPilot**. Журнал должен подтвердить `новый выпуск создан`.
   Если вопросы совпадают с прошлым активным выпуском и он уже пройден тестировщиком,
   использовать `cfActivateRepeatPilot` ТОЛЬКО после проверки текущего выпуска.
3. Cloudflare Worker → Settings → Variables and Secrets:
   - ACCESS_MODE = `public`;
   - WEBHOOK_SECRET = случайный секрет 32–256 символов из `A–Z a–z 0–9 _ -`;
   - INVITES_ENABLED = `no`; WEEKLY_ENABLED = `no`;
   - не изменяй BOT_TOKEN, ADMIN_KEY, TEST_CHAT_ID, DB.
4. GAS → Script Properties: `CF_RELEASE_APPROVED = YES`. Этот флаг
   ничего сам не переключает, только разрешает ручные команды.
5. GAS: **cfReleasePreflight**. Проверить:
   `placeholderCount=0`, `questionCount=6`, `launchUrl` содержит `quiz.html`,
   `accessMode=public`, имя бота соответствует `posttsop_test_bot`.
   **Если что-то не так — остановиться.**
6. GAS: **cfReleaseSwitchWebhook**. Только здесь меняется сервер /start у Telegram.
   Функция сохраняет предыдущий webhook URL в приватных Script Properties.
7. GAS: **cfReleasePreflight** ещё раз: `Webhook` должен стать
   `https://vychitat.fr-novii.workers.dev/telegram`.
8. GAS: **cfReleaseSwitchMenu**. Кнопка меню начинает открывать финальный тест.
9. Ручная проверка: отправить боту `/start`, открыть кнопку из ответа,
   убедиться, что открывается `quiz.html` и виден новый выпуск (не старые 4/6).
10. После подтверждения можно публиковать пост в канале со ссылкой
    https://t.me/posttsop_test_bot?start=quiz .

## Приглашения (не обязательны для запуска)
- Канальные подписчики не становятся автоматически пользователями бота.
  Telegram позволяет написать только пользователям, которые уже запускали бота.
- При необходимости GAS: **cfImportMiniContacts** — перенесёт известных боту пользователей
  из Google Sheets в Cloudflare (без сообщений).
- Когда /start и меню проверены: INVITES_ENABLED = `yes`, потом
  вручную **cfReleaseInvite20**. Она отправит до 20 приглашений.
- Для дальнейших пакетов нужен отдельный Cron Trigger `*/5 * * * *`
  либо повторные ручные вызовы. Не включать Cron, пока не проверены первые приглашения.

## На следующие вторники
Не включать `WEEKLY_ENABLED=yes` до отдельной проверки еженедельного сценария.
Рабочий Cron Worker `0 7 * * 2` означает **10:00 по Москве**;
настройки Cron распространяются не мгновенно (до 15 минут).
По понедельникам можно передавать свежие вопросы через `cfInstallMondayQuestionSync`.

## При сбое
- Не удалять D1, не менять Telegram-токен и не создавать новые выпуски повторно.
- Остановить приглашения (`INVITES_ENABLED=no`).
- В GAS Script Properties `CF_PREVIOUS_WEBHOOK_URL` хранится прежний адрес
  (он может содержать секретный параметр, не публиковать его).
- Вернуться к предыдущему webhook и меню можно отдельно вручную.
- Отметить в журнале GAS, на каком шаге возникла ошибка.
