# Техническая проверка Mini App ↔ Google Apps Script

**Это тест соединения, а не полноценный backend.** Не заменяет действующий бот.

Почему нужно проверить: браузерный `fetch` из GitHub Pages к обычному GAS ContentService может не получить ответ из-за CORS/редиректов. Поэтому сначала проверяется связка:
- GET через JSONP (только для безопасных данных; никаких секретов и правильных ответов).
- POST с `mode: 'no-cors'` и `Content-Type: text/plain`. Поскольку ответ непрозрачен, результат обработки отдельно проверяем через GET.

## Как запустить (когда будем готовы)

1. Создать **новый отдельный проект Apps Script** на https://script.google.com/ — действующий бот и таблицу не трогать.
2. Вставить в `Code.gs` код из `backend/BridgeProbe.gs`, сохранить.
3. Нажать **Deploy → New deployment → Web app**.
4. Execute as: **Me**. Who has access: **Anyone** (иначе запросы от Mini App не дойдут).
5. Скопировать публичный адрес опубликованного Web App, заканчивающийся на `/exec`.
6. Открыть `bridge-test.html` с GitHub Pages, вставить адрес и нажать «Проверить соединение».

Обрати внимание: это **только тест** — код ничего не пишет в Google Sheets, не читает ответы, не получает Telegram IDs, не отправляет сообщения. В проекте GAS пока не надо прописывать BOT_TOKEN.

## Дальше, если тест пройдёт

1. Мини-приложение получает вопросы из таблицы, но правильные ответы и объяснения до проверки не публикуются.
2. Бэкенд GAS проверяет `Telegram.WebApp.initData` по подписи Telegram и сроку действия; пользовательские ID нельзя брать из `initDataUnsafe` без проверки.
3. Ответы сохраняются атомарно и только один раз для пользователя и выпуска.
4. В 19:00 (Москва) бот рассылает текущую статистику только в процентах по каждому из шести вопросов, **без минимального числа участников**. Администратор видит абсолютные значения.
5. После 19:00 завершившие тест видят актуальные проценты.
6. Отдельно реализуем списки отправок и идемпотентность, чтобы не дублировать сообщения.

Нельзя переносить этот тестовый открытый backend непосредственно в продакшн: перед запуском настоящих тестов нужны аутентификация, проверка ответов на сервере и обработка ошибок.
