# Публикация существующего Worker из GitHub

Worker: `vychitat`. Репозиторий: `franznovii/russian-language-quiz`.
Конфигурация в корне: `wrangler.jsonc`.

## Настройки Cloudflare → Settings → Builds

- Production branch: `main`.
- Root directory / Path: корень репозитория (`/`).
- Build command: пустое поле (отдельная сборка не нужна).
- Deploy command: `npx --yes wrangler@4.153.0 deploy --config wrangler.jsonc`.
- После проверки настроек включить автоматические сборки (Disable builds — выключен).

Если репозиторий подключён с выключенными сборками, сохранить эти параметры,
включить сборки, затем запустить новую публикацию. Настройка связи с GitHub сама
по себе не подтверждает, что версия уже развёрнута: нужен успешный deployment.

## Сохранение существующих данных и настроек

Конфигурация привязывает `DB` к уже существующей D1-базе
`494733ab-b9da-4b92-8479-2b68d2ad785f` в аккаунте
`13282711f1f1e4c734eb2bf9a6482ab5`. Команда публикации не выполняет SQL,
миграции, создание выпусков или очистку результатов.

`keep_vars: true` сохраняет переменные, установленные в панели Cloudflare,
включая режим доступа и переключатели рассылок. Секреты Wrangler сохраняет
при обычном deploy; их значения в репозиторий не добавляются.
Расписания Cron и пользовательские маршруты здесь не задаются.

## Проверка перед публикацией

```sh
npx --yes wrangler@4.153.0 deploy --config wrangler.jsonc --dry-run --outdir /tmp/vychitat-worker-check
```

Это проверка сборки без публикации и без запросов к базе. Она не подтверждает
наличие прав у сборщика Cloudflare и правильность серверных секретов.

## Проверка после публикации

1. В журнале сборки должна завершиться команда deploy без ошибок; публикация
   должна стать активной.
2. Проверить `https://vychitat.fr-novii.workers.dev/`:
   ожидается `vychitat Mini App: Worker + D1 OK`.
3. В боте нажать «Статистика»: должен появиться блок «Для поста» с семью
   строками `0/6 - …%` — `6/6 - …%`.

Автоматическая публикация кода не меняет доступность Cloudflare у провайдеров.
